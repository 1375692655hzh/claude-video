# 视频稿阶段：工作流①–⑤

完成人设与平台选择，得到用户确认的视频成稿。三个执行目录和十步总流程见上一层 `../AGENTS.md`。

> **新项目（2026-11-02 起）**：每期内容不再放在本文件夹的 `<期名>/`，而是 `../projects/YYYY/MM/<项目ID>/`。先 `npm run project -- new <英文短名>` 建项目；
> 下文的 `<期名>/00-项目设置.md`、`01-初稿.md`、`02-外部建议.md`、`03-终稿-en.md` 对应项目里的 `00-项目设置.md`、`01-视频稿/…`，
> 人设确认后 `npm run project -- set <ID> persona=<名字>`，平台确认后 `set <ID> platform=<youtube-long|youtube-shorts|instagram-reels|tiktok> step=3`；
> 用户确认成稿后 `set <ID> finalConfirmed=true`；用户明确决定不做④外审时 `set <ID> adviceSkipped=true`（否则缺 `02-外部建议.md` 过不了⑥门禁）；
> 用户直接交付成稿用 `npm run project -- final <ID> <文件>`。完整对照见 `../AGENTS.md`「路径对照」。本文件夹的 `<期名>/` 只剩旧期。

## 目录

```
_人设/                    预存人设；人设模板也在这里
platforms/               四种平台 / 视频方式规范
standards/去AI味.md       去 AI 味综合清单
templates/               项目设置、视频稿、外部建议、发布包装等模板
consult/                 可复制到 Grok / Gemini 的外审提示词；agy 仅作可选工具
_参考稿/                  用户认可的历史稿件，只学语气和节奏，不搬事实
<期名>/                  旧期（YYYY-MM-<英文短名>）；新项目在 ../projects/
```

## 主流程

| 工作流 | 产出（`<期名>/` 下） | 做法 | 停下等用户？ |
|---|---|---|---|
| ① 选择人设 | `00-项目设置.md` + 人设文件 | 列出 `_人设/` 的预存人设；选“新人设”时按 `_人设/人设模板.md` 整理用户输入，保存后使用 | **是：确认人设** |
| ② 选择平台和视频方式 | 更新 `00-项目设置.md` | 四选一：YouTube 长视频 / YouTube Shorts / Instagram Reels / TikTok；确定语言、画幅、目标时长、直接选题或由长视频改编 | **是：确认完整设置** |
| ③ 视频初稿 | `01-初稿.md` | 按人设、所选平台规范和素材在仓库对话中生成；事实与数据有出处，不确定处标出 | 否 |
| ③ 直接交付成稿 | `03-终稿-en.md`（或用户指定的发布语言文件） | 用户明确说交付的是成稿时，登记为标准成稿，**跳过④⑤，直接进⑥**；不强制补中文底稿或重复去 AI 化 | **成稿本身须已获用户确认** |
| ④ 修改建议 | `02-外部建议.md` | 用户自行拿初稿去 Grok / Gemini 问询并贴回；保存原回复、采纳 / 驳回和理由，不自动调用外部智能体 | **等用户贴回建议** |
| ⑤ 视频成稿 | `03-终稿-en.md`；有中文底稿时保留 `03-终稿.md` | 逐条处理建议，按 `standards/去AI味.md` 和所选人设 / 平台规范修改；用户人工改稿并确认 | **是：确认成稿后才进⑥** |

发布包装和发布后复盘是附加流程，不阻塞第⑥步。需要时做 `04-发布包装-<平台>-en.md` 和 `05-复盘.md`，规范见所选平台文件。

## ① 人设规则

- 预存人设是可复用文件，不从历史对话里猜人设。新人设也先整理成 `_人设/<名字>.md`，用户确认后写入 `00-项目设置.md`。
- 人设决定身份、受众、语言、内容边界、语气、经历和视觉偏好；平台规范决定平台机制与视频结构。两者冲突时停下让用户确认，不静默覆盖。
- 不编造主持人的履历、资质、投资成绩、所在地或个人观点。用户没提供的字段留空或写“不公开”。
- Andy 是预存人设之一，不再是所有新期的默认唯一主持人。历史稿件保持原样。

## ② 平台规则

| 选择 | 规范 | 默认画幅 | 说明 |
|---|---|---|---|
| YouTube 长视频 | `platforms/youtube-long-en.md` + 通用 `youtube-long.md` | 16:9 | 主线；发布包装和复盘规范最完整。**最高优先级：`youtube-long.md`〇.5「前紧中稳后强」五段结构**（15–25 分钟、10 秒抓人、30 秒悬念、每 3–4 分钟换挡、数据反转、结尾强引导互动） |
| YouTube Shorts | `platforms/youtube-shorts-en.md` | 9:16 | 可直接选题，也可从长视频改编 |
| Instagram Reels | `platforms/instagram-reels-en.md` | 9:16 | 可直接选题，也可从长视频改编 |
| TikTok | `platforms/tiktok-en.md` | 9:16 | 可直接选题，也可从长视频改编 |

平台规范里的时长、字数和安全区如标为“起步值”，不是平台官方最佳值；有真实后台数据后再调整。

## ③–⑤ 稿件规则

- 初稿、外审建议、成稿分文件保存，不用覆盖初稿的方式“修改完就算成稿”。
- 中文底稿用于审逻辑和事实；英文发布稿是改写（transcreation），不是逐句翻译。用户直接交付英文成稿时，不强制倒补中文稿。
- 第④步的原始回复要保留。第⑤步逐条写采纳 / 驳回；外部建议里无出处的数字、事实和更强判断不能直接进入成稿。
- 中文稿用 `humanizer-zh`，英文稿用 `humanizer`，再按 `standards/去AI味.md` 检查。AI 只提供修改候选，**用户人工修改并确认后才叫成稿**。
- 成稿是第⑥步的唯一口播依据。后续要改口播，回本阶段修改并重新确认，不在脚本或视频生成阶段顺手改。

## 信源规则（默认英文财经人设必须遵守；口播和画面字卡都适用）

- **能点名的信源只有三类**：知名投行（高盛、摩根士丹利、摩根大通、美银、花旗、瑞银、伯恩斯坦等）、
  知名研究 / 数据机构（彭博、LSEG、FactSet、皮尤研究中心、Gartner、IDC 等）、金融和企业界名人（巴菲特、黄仁勋、皮查伊等）。
  公司自己的财报、SEC 文件、电话会和管理层原话是一手资料，一直可以用。
- **其他来源不点名**：海豚研究、长桥、华尔街见闻、富途、公众号、自媒体、财经资讯站都不在名单里，也不能说“有机构认为”来暗指。
  它们只能当线索：事实要用财报或上述三类信源核实后再用，并按核实到的来源署名；它们自己的测算、调研、推断核实不到就删。
- 稿内“（来源：……）”写真实出处，方便核对，不口播。没有具名的“市场一致预期”可以用，但标注里写清是谁统计的。
- 新人设如有不同领域或信源要求，必须写进人设文件并由用户确认；不能借新人设绕过事实核查。

## 从长视频改编短视频

- 源头是用户确认的长视频成稿；只能删、合并、换说法，不新增长视频没有的事实、数字和判断。
- 同一期拆多条时，视频稿放 `<期名>/<平台短名>/`，脚本和视频生成沿用相同期名与平台短名。
- 直接选择 Shorts / Reels / TikTok 做独立视频时，走标准①–⑩，不强制先存在长视频。

## 常用命令（在本文件夹运行）

| 用途 | 命令 |
|---|---|
| 拉腾讯文档（正文 + 图片） | `npm run fetch-doc -- <链接> <期名>/素材.md` |
| 生成封面（整张，提示词只给内容） | 从 Bash：`npm run image -- "$(cat 提示词.txt)" <期名>/cover/A-en.png --size 1920*1080 --n 2` |
| Codex 生图 | `npm run image-codex -- <提示词或.txt> <输出.png> [--n 2]` |
| 可选：问 agy 第二意见 | `npm run consult -- <问题或.md> --file <文件> --out <回答.md>` |

`npm run consult` 不是第④步的默认执行方式。第④步默认由用户自行去 Grok / Gemini 问询并贴回；任何外部智能体都不能未经用户点名自动调用。
