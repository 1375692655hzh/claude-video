# 脚本阶段：工作流⑥–⑨

把用户确认的视频成稿做成“脚本初稿”，完成素材搜寻与人工补全，再根据真实素材重排为“脚本成稿”。十步总流程见上一层 `../AGENTS.md`。

> **新项目（2026-11-02 起）**：本阶段的产物写在 `../projects/YYYY/MM/<项目ID>/` 里：`02-脚本/script-draft.md`、`assets.md`、`script.md`，
> 人工材料放 `03-素材/原始/`，参考图放 `03-素材/refs/`；脚本里引用素材写项目内相对路径。进⑨前跑 `npm run project -- check <ID> --step 9`，
> 进⑩前跑 `--step 10`，有 ✗ 不过闸门。完整对照见 `../AGENTS.md`「路径对照」。本文件夹的 `<期名>/` 只剩旧期。

## 输入与输出

### 输入

- `../1-视频稿/<期名>/00-项目设置.md`：人设、平台、画幅、语言、来源模式。
- 项目设置指定的人设文件与平台规范。
- `../1-视频稿/<期名>/03-终稿-en.md`：口播原文；有中文 `03-终稿.md` 时一起读，供理解内容。
- **这一步不改口播文字**。要改回视频稿阶段（①–⑤），修改并重新确认后再回来。

### 输出（都在 `<期名>/`）

| 文件 / 目录 | 工作流 | 含义 |
|---|---|---|
| `script-draft.md` | ⑥ | 脚本初稿，允许候选画面和“待找”素材 |
| `assets.md` | ⑦⑧ | 持续更新的素材与缺口台账 |
| `材料/` | ⑧ | 用户人工补充的截图、录屏、图片、视频、文档等 |
| `refs/` | ⑨ | 至少一张用户确认的视频风格参考图 |
| `script.md` | ⑨ | 根据完整素材重排、用户确认后的唯一脚本成稿，交第⑩步 |

## ⑥ 脚本初稿

1. **读懂内容和设置**：通读成稿、中文底稿（如有）、人设和平台规范，列出核心论点、关键数据和必须“看见”的对象。
2. **初步定风格**：配音音色、数字人出镜方式、背景音乐、字幕，以及视觉主题。现有动效主题为 `cards`（浅灰白卡片，默认）或 `navy`（深海军蓝），字体 Inter；新风格在第⑨步用参考图确认。
3. **切初步分镜**：按口播原文切镜，不改字。长视频每镜通常 3–8 秒；竖屏短视频通常 1.5–4 秒，平台规范另有要求时以它为准。
4. **写逐镜素材需求**：素材视频 / 图片 / 生成图 / 图表动画 / 文字卡 / 数字人；把“要表现什么”和“缺什么”写清。
5. **初拟页面与动效**：优先从 `../3-视频生成/effects/_shared/motion/README.md` 选 ID，写关键参数和触发词；库里没有写“新动效：<描述>”。
6. 输出 `script-draft.md` 和 `assets.md` 的初始需求。**初稿不是可生成交接件，不因为写了分镜就跳到第⑩步。**

脚本初稿可在本仓库对话中完成，也可由用户拿视频成稿去 GPT / Claude 完成后贴回。项目不自动调用这些外部智能体；外部结果仍按本阶段模板验收。

## ⑦ 素材搜寻

1. 按 `assets.md` 的需求逐条**先查库**：`npm run assets -- search <关键词>`。
2. 库里没有的，按 `../shared/asset-library/grok-prompt-template.md` 准备搜索需求；经用户明确选择后再用 Grok 等外部工具找源。
3. 导入候选、核实可用性、生成缩略图：`import` → `verify` → `thumbs`；不合适用 `reject` 留原因，避免下次重复。
4. 记录素材库 ID、可用片段、来源、授权和备选。找不到的保留“待找”，不能编造链接或把未看过的候选写成已确认。
5. **本阶段不下载正式片段**；第⑩步按最终脚本的库 ID + 秒数片段下载。

素材来源优先不用登录、能直接下载且授权清晰的来源。YouTube 只作补充，并尽量给非 YouTube 备选：
- 火箭、航天：NASA 图片视频库（公有领域，有 mp4 直链）。
- 公司画面：公司新闻站、官方博客和官方账号。
- 人物：Wikimedia Commons 的 CC / 公有领域照片，按页面署名。

## ⑧ 素材补全：人工补件 + 二次补缺

1. **先列人工补件清单**：把用户更方便取得的项目单独列出，例如个股行情和股价截图、财报原文截图、产品录屏、自有照片或内部文档；写清镜头、内容、画幅、时间点、格式和截止时间（如有时效）。
2. **停下等用户补件**。用户文件放 `<期名>/材料/`，不要只留在聊天附件或外部临时链接里。
3. 在 `assets.md` 登记本地路径、来源、授权、实际内容和可用片段；逐项核对文件是否可读、是否选对了时间和对象。
4. **重新跑缺口检查**：已解决的关闭，剩余缺口再次走第⑦步搜索；不能用无关素材凑数。必要时重复“人工补件 → 再搜”。
5. 只有所有镜头都有可用素材，或用户明确批准生成图 / 图表 / 文字卡等替代方案，才可申请“素材补齐确认”。**这是进入第⑨步的人工闸门。**

人工本地素材没有专用 `assets register` 命令时，以 `assets.md` 为登记台账，不强行伪造 URL 导入素材库。第⑩步再把要用的文件复制到 `public/<期名>/` 并记录最终路径。

## ⑨ 根据完整素材重排脚本成稿

1. **看真实素材再排**：根据实际画面内容、横竖画幅、清晰度、时长、可用片段和授权重排，不是把 `script-draft.md` 里的“待找”简单替换成链接。
2. **确认风格参考图**：`refs/` 至少一张，用户明确确认。脚本写清参考图路径，以及要继承的版式、配色、字体、卡片 / 镜头运动和禁止继承的内容。
3. 最终 `script.md` 写全：逐镜口播、画面、素材库 ID + 片段或人工文件路径、动效 ID + 参数 + 触发词、字幕、转场、配乐音效、数字人和来源标注。
4. 音效只在章节切换、关键结论和关键数据处标注，遵守 `../3-视频生成/public/library/README.md`。
5. **成稿门禁**：
   - 没有未批准的“待找 / 未核实 / 待定片段”；
   - 实拍镜头都有精确素材位置，生成素材有用户认可的明确方案；
   - 参考图已确认，素材与画面设计一致；
   - 口播与视频成稿一致；
   - 用户明确确认“脚本成稿，可交第⑩步”。
6. 第⑩步若发现素材或风格问题，回第⑦⑧补素材，或回第⑨步修改并重新确认；不在制作时静默改设计。

## 竖屏平台与长视频拆条

- YouTube Shorts / Instagram Reels / TikTok 都是 1080×1920、30fps；全程烧录字幕，安全区按所选平台规范和实际 App 预览核对。
- 直接选题使用同一期名的标准产物；从长视频拆多条时，在 `<期名>/<平台短名>/` 放下属脚本与素材台账，沿用长视频可复用素材，但按真实竖屏构图重排。
- 第三方片段、首秒字卡、封面安全区和音效限制以所选平台规范为准，不把 YouTube 长视频的台标或订阅动画带到其他平台。

## 常用命令（在本文件夹运行）

| 用途 | 命令 |
|---|---|
| 查素材库 | `npm run assets -- search <关键词> [--domain 半导体] [--shot 产品特写]` |
| 导入 / 核实 / 缩略图 | `npm run assets -- import <grok.json> --project <期名>` / `verify --unverified` / `thumbs --missing` |
| 拉腾讯文档材料 | `npm run fetch-doc -- <链接> <期名>/材料/xx.md` |
| 出草图 / 参考图 | `npm run image -- "提示词" <期名>/refs/ref-01.png` |
| 可选：问 agy 意见 | `npm run consult -- "问题" --file <期名>/script-draft.md --out <期名>/agy建议.md` |

素材库字段和分类见 `../shared/asset-library/README.md`；YouTube cookies、限速和外部工具调用边界见 `../AGENTS.md`。
