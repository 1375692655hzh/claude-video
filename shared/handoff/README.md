# shared/handoff/：外部交付提示词库

十步里有些环节交给外部工具做更合适：Grok 搜索和核实、Gemini 审稿、Codex 写分镜或跑本机工具、用户本人补截图。
这里放这些环节的**提示词模板**；每次交出去，都用 `project handoff` 命令在项目里生成一份具体的提示词文件，
不在聊天里临时手写长提示词。

## 交付点总表

| 模板 | 工作流 | 推荐外部工具 | 交出去做什么 | 回收到哪里 | 回收后谁验收 |
|---|---|---|---|---|---|
| `H01-外审-爆款与逻辑` | ④ | Grok + Gemini（两家都问） | 初稿是否达到平台爆款要求、逻辑是否成立、标题与开头改写 | `01-视频稿/02-外部建议.md`（E1、E2…原文） | Claude 在⑤逐条处理 |
| `H02-事实与时效核查` | ⑤确认前、⑨确认前、⑩录音前 | Grok（开搜索） | 逐条核数字和说法；**查截至今天的新进展**（交易、财报、股价） | `08-外部交付/<编号>-回复.md` | Claude 判断是否回视频稿阶段 |
| `H03-脚本初稿` | ⑥ | Codex（仓库内）/ GPT | 按成稿切分镜、定逐镜画面和素材需求 | `02-脚本/script-draft.md`、`assets.md` | Claude 按 `2-脚本/AGENTS.md` 验收 |
| `H04-素材搜寻` | ⑦ | Grok（网页 / App）或 Codex 调 Grok CLI | 按需求清单找真实可用的视频、图片、原文页链接 | `08-外部交付/<编号>-回复.md`（JSON）→ `npm run assets -- import` | Claude 导入、核实、看缩略图 |
| `H05-人工补件清单` | ⑧ | 用户本人 | 股价截图、付费报道截图、录屏等只有用户方便取得的材料 | `03-素材/原始/` | Claude 逐项核对并登记 `assets.md` |
| `H06-发布包装` | ⑩出片后 | Grok / Gemini | 3 个测试标题、封面大字、简介、章节、置顶评论的审读与改写 | `06-交付/<平台>/发布包装.md` | Claude 合并、用户定稿 |
| `H07-数字人` | ⑩（可选） | Codex + Topview 插件 | 用配音和形象照生成数字人口播片段 | `04-音频/host/` | Claude 检查口型、时长后接入 |

## 命令

```
npm run project -- handoff <ID> list                         # 模板清单 + 本项目已交付记录
npm run project -- handoff <ID> new H02 --tool grok [--note "⑨前复核"]   # 生成提示词文件 + 空回复文件，登记到 project.json（状态：待填写）
npm run project -- handoff <ID> send <编号>                   # Claude 填完 {{填写}} 后：检查无遗漏、标记已发出、写 next
npm run project -- handoff <ID> done <编号>                   # 回复已贴回，标记待验收
npm run project -- handoff <ID> close <编号> [--note "已采纳 3 条"]     # 验收完成
```

生成的文件在项目的 `08-外部交付/`：

```
08-外部交付/
  01-H01-外审-爆款与逻辑-grok-提示词.md   ← 发给外部工具的完整提示词（含「复制开始 / 复制结束」块）
  01-H01-外审-爆款与逻辑-grok-回复.md     ← 用户把外部工具的原始回复整段贴在这里（或贴给 Claude 由 Claude 存）
```

## Claude 交给外部时必须做的五件事（硬规则）

1. **生成文件**：用 `handoff new` 生成提示词文件，把模板里所有 `{{填写:…}}` 换成本期真实内容（命令会检查遗漏；`{{自动:…}}` 由命令自动填）。
2. **在聊天里给用户四样东西**（缺一样都算没交付）：
   - 提示词文件的完整路径（相对仓库根目录）；
   - 需要一起附给外部工具的文件路径（没有就写“无需附件”）；
   - 可直接复制的提示词正文（短于约 3000 字时全文贴出；更长时贴出前 20 行并说明“整段复制文件里两条分隔线之间的内容”）；
   - 回收方式：回复贴到哪个文件、要求的格式（原文逐字 / JSON / 表格），以及贴回后对 Claude 说什么。
3. **登记**：命令自动写进 `project.json` 的 `handoffs`；`project.json` 的 `next` 写“等待外部交付 <编号> 回收”。
4. **停下等回收**：不替外部工具编造结果；外部回复里的说法要核实后才进稿件或素材台账。
5. **回收验收**：用户贴回后跑 `handoff done`，Claude 验收、处理完跑 `handoff close`，并在对应阶段文件里记录采纳与驳回。

## 写模板的约定

- `{{自动:项目ID}}`、`{{自动:项目目录}}`、`{{自动:今天}}`、`{{自动:人设}}`、`{{自动:平台}}`、`{{自动:回复文件}}`、`{{自动:编号}}`：命令自动替换。
- `{{填写:说明}}`：Claude 必须替换；`project check` 发现残留会报错。
- 发给外部工具的正文写在 `===== 复制开始 =====` 与 `===== 复制结束 =====` 之间；分隔线以上是给用户看的用法说明。
- 外部工具读不到本仓库时（网页版 Grok / Gemini），正文必须**自带**所需内容（稿件全文、规则摘录），不能只写文件路径。
  Codex 在仓库里运行时可以只写文件路径。
- 信源规则、不编造链接、不画已成交画面等硬约束，每个模板都要带上。
